**카테고리**: AI/NLP · 텍스트 일관성 검사
**스택**: Python, SQLite, sentence-transformers (all-MiniLM-L6-v2), Click
**날짜**: 2026-03-08

# Background

## AI 시대, 장편 콘텐츠의 일관성 문제

- LLM으로 장편 소설을 쓰거나, 에이전트로 긴 워크플로를 처리하는 일이 흔해졌다
- 컨텍스트 윈도우가 아무리 늘어나도 **200만 자 이상**의 텍스트를 한 번에 처리하긴 어렵다
- 결과: 캐릭터의 눈 색깔이 바뀌고, 죽은 캐릭터가 재등장하고, 설정이 뒤집힌다
- 사람이 수동으로 추적하는 건 한계가 있고, 기존 도구들은 특정 플랫폼에 종속되어 있다

<!--

# Solution

## 접근법: LLM 없이 로컬에서 도는 사실 추적 + 모순 탐지 CLI

**핵심 아이디어**: 규칙 기반으로 사실을 추출하고, 임베딩 유사도로 모순을 탐지한다

기존 도구와의 차이점:
- **플랫폼 독립**: 어떤 에디터, 어떤 LLM과도 조합 가능
- **로컬 완결**: 원고 데이터가 외부로 나가지 않음
- **LLM 호출 제로**: sentence-transformers 경량 모델만 사용
- **CLI 기반**: 파이프라인에 자연스럽게 통합 가능

검증 목표: *"사실을 자동 추출하고 모순을 탐지하여, 수동 추적 없이 일관성 오류를 발견할 수 있는가"*

<!--
그래서 이걸 왜 만들었냐면, LLM을 호출하지 않고도 로컬에서 사실 추적과 모순 탐지가 되는 도구를 만들어 보자는 거였다. 접근은 두 단계다. 먼저 규칙 기반 regex로 텍스트에서 사실을 뽑아서 SQLite에 저장한다. 그 다음 새 텍스트가 들어오면 기존 사실과 비교하는데, 같은 엔티티의 같은 속성이면 직접 값을 비교하고, 다른 속성이라도 임베딩 유사도가 높으면 잠재적 모순으로 플래그를 띄운다. 이중 검사 구조다.
-->

# Architecture

```
┌─────────────────────────────────────────────────────────────────────┐
│                          CLI (cli.py)                               │
│         Click 기반 커맨드: init / extract / check / context         │
└──────┬──────────┬───────────────┬───────────────┬───────────────────┘
       │          │               │               │
       ▼          ▼               ▼               ▼
┌──────────┐ ┌──────────────┐ ┌──────────────┐ ┌──────────────────┐
│  init    │ │   extract    │ │    check     │ │     context      │
│ DB 초기화 │ │ 사실 추출 +  │ │ 신규 vs 기존 │ │ 토큰 예산 내     │
│          │ │ 임베딩 저장   │ │ 이중 비교    │ │ 관련 사실 선별   │
└──────────┘ └──────┬───────┘ └──────┬───────┘ └────────┬─────────┘
                    ▼                ▼                   ▼
           ┌──────────────────────────────────────────────────────┐
           │                   db.py (SQLite)                     │
           │  facts: entity | attribute | value | source | embed  │
           │  sentence-transformers (all-MiniLM-L6-v2) 임베딩     │
           └──────────────────────────────────────────────────────┘
```

- **extractor.py**: 6종 regex 패턴으로 사실 추출 (외모, 위치, 관계, 나이 등)
- **checker.py**: Phase 1 직접 비교 + Phase 2 임베딩 교차 비교
- **context.py**: 코사인 유사도 랭킹 → 토큰 예산 내 스니펫 패킹

<!--
구조를 보면, CLI가 네 개의 커맨드를 제공한다. init으로 DB를 만들고, extract로 텍스트에서 사실을 뽑고, check로 모순을 찾고, context로 현재 씬에 맞는 사실 스니펫을 만든다. 사실 추출은 extractor.py에서 6종류의 regex 패턴으로 한다. 외모 묘사, 위치, 관계, 나이 같은 것들. 모순 탐지는 checker.py에서 두 단계로 한다. 먼저 같은 엔티티의 같은 속성값을 직접 비교하고, 그 다음 임베딩 유사도로 교차 비교한다. 전부 SQLite 하나에 저장되니까 의존성이 가볍다.
-->

# Demo

## 핵심 시나리오: Elena의 눈 색깔이 바뀌다

```bash
# 챕터 1에서 사실 추출
$ uv run consistency extract sample_data/chapter1.txt -d sample_data
✓ Extracted 8 facts from chapter1.txt
  [Chapter 1] Elena.eye_color = deep green
  [Chapter 1] Elena.hair = long dark
  [Chapter 1] Elena.occupation = a scholar

# 챕터 3에서 모순 탐지
$ uv run consistency check sample_data/chapter3.txt -d sample_data
⚠ Found 3 potential inconsistencies:

⚠ INCONSISTENCY: Elena.eye_color changed: 'deep green' → 'bright blue'
  Fact A: Elena.eye_color = deep green (Chapter 1, line 5)
  Fact B: Elena.eye_color = bright blue (Chapter 3, line 12)
  Similarity: 0.847
```

**결과**: 의도적으로 넣은 모순 **6건 전부 탐지**, false positive 임계값 조정으로 제거

<!--
데모를 보면, 챕터 1에서 Elena의 눈이 deep green이라고 추출했다. 그런데 챕터 3에서 bright blue라고 나온다. 이걸 자동으로 잡아낸다. 의도적으로 넣은 모순 6건을 전부 탐지했다. 처음에는 cross-attribute에서 false positive가 2건 나왔는데, 임계값을 0.5에서 0.6으로 올려서 해결했다. 유의미한 cross-attribute 모순은 살리면서 노이즈만 제거한 거다.

# Key Decisions & Lessons

## 기술 판단

| 판단 | 선택 | 이유 |
|------|------|------|
| 사실 추출 방식 | regex 패턴 (spaCy 대신) | 경량화 우선. 프로토타입에서 NLP 파이프라인은 과잉 |
| 모순 탐지 | 이중 검사 (직접 비교 + 임베딩) | 직접 비교만으론 cross-attribute 모순을 놓침 |
| 임계값 튜닝 | 0.5 → 0.6 | false positive 2건 제거, 유의미한 탐지 유지 |

## 심의 점수 & 반대 의견

- 문제 진정성 **4.0/5** · 프로토타입 적합성 **2.7/5** · 학습 가치 **3.7/5**
- 반대 의견 (서연): *"규칙 기반/임베딩만으로는 데모 품질이 빈약할 위험"*
  → 결과적으로 regex + 임베딩 이중 검사가 꽤 유효하게 동작했다

<!--
기술 판단 몇 가지를 짚어보면, 사실 추출을 spaCy 같은 NLP 파이프라인 대신 regex로 한 건 의도적인 선택이었다. 프로토타입에서 무거운 의존성을 끌어오면 본질이 흐려진다. 모순 탐지를 이중 구조로 한 것도 중요한 판단이었다. 같은 속성 직접 비교만으로는 "나이 52세인데 설명은 젊다"는 식의 cross-attribute 모순을 놓친다. 심의에서 서연이 규칙 기반만으로는 빈약할 거라고 반대했는데, 솔직히 맞는 우려였다. 근데 임베딩을 같이 쓰니까 꽤 괜찮았다. 프로토타입 적합성이 2.7로 낮게 나온 것도, 결과적으로는 범위를 잘 잡아서 동작하는 데모가 나왔다.
-->

# Results & Future

## 성과

- ✅ 4개 CLI 커맨드 전부 동작 (init / extract / check / context)
- ✅ 의도적 모순 **6건 전부 탐지** (목표 3건 이상)
- ✅ 토큰 예산 내 컨텍스트 스니펫 생성 동작
- ✅ LLM 호출 제로, 로컬 완결

## 한계점

- regex 기반 추출은 **복잡한 문장 구조**에 취약 (대명사 해소 없음)
- cross-attribute 탐지의 **정밀도**는 아직 개선 여지가 있다
- 영어 단일 언어만 지원

## 프로덕트가 되려면

- LLM 기반 사실 추출로 전환 (규칙 기반은 커버리지 한계)
- 에디터 플러그인 (VS Code, Obsidian) 연동
- 시간 순서·인과관계 모순 탐지 추가
- 다국어 지원, 실시간 스트리밍 분석
