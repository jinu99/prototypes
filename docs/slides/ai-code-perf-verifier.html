카테고리: Developer Tools / Code Quality 스택: Python, AST, Git, Rich, uv 날짜: 2026-03-08

Background

AI 코드 생성 시대의 사각지대

  • AI 코딩 도구(Copilot, Cursor 등)가 일상이 된 시대
  • 생성된 코드는 컴파일되고, 테스트를 통과한다
  • 하지만 비기능적 품질(성능, 메모리)은 아무도 안 본다

왜 지금 이슈인가

  • SQLite를 LLM으로 재작성했더니 기본 키 조회가 20,000배 느린 사례
  • AI 생성 코드의 검증 부채(verification debt)가 누적되는 중
  • "돌아가니까 OK" → 프로덕션에서 성능 장애로 돌아온다

Pain Point

커뮤니티에서 반복되는 목소리

#출처SignalPain Point
1GeekNews3/3LLM이 생성한 코드가 테스트를 통과하지만 성능이 수만 배 느린 등 비기능적 품질이 심각
2Hacker News3/3AI 코드의 검증 부채가 쌓여 사후 확인 비용이 증가
3r/webdev3/3AI 코드가 레거시 코드베이스에서 안전하게 동작하는지 증명할 방법이 없다

Signal 3/3: 여러 쓰레드에서 반복적으로 언급되는 강한 신호

Solution

접근법

"Git diff에서 변경 함수를 자동으로 찾고, 기존 테스트로 성능을 측정한다"

기존 도구와의 차이

기존 도구한계우리 접근
pytest-benchmark변경분 자동 식별 없음Git diff → AST로 변경 함수만 타겟
GreptileAI 리뷰 품질 벤치마크실제 실행 시간/메모리 비교
Exceeds AISaaS, 실시간 아님로컬 CLI, 즉시 실행

핵심 아이디어

벤치마크를 새로 만들지 않는다. 이미 있는 테스트를 벤치마크로 재활용한다.

Key Decisions & Lessons

기술 판단

판단선택이유
벤치마크 방식기존 테스트 재활용자동 입력 생성은 범위 밖. 테스트가 이미 유의미한 입력을 제공
의존성Rich만 사용ast, subprocess, tracemalloc 모두 표준 라이브러리로 해결
변경 함수 식별AST 파싱regex 매칭보다 정확. 클래스 메서드까지 처리 가능

시행착오

  • flat layout에서 모듈 import 실패 → 패키지 구조로 전환
  • 터미널 테이블이 폭 초과 → 컬럼 8개에서 6개로 축소

심의 점수

문제 진정성 4.0/5 · 프로토타입 적합성 3.3/5 · 학습 가치 3.7/5 패널 만장일치 승인

Results & Future

성과 (5/5 통과)

  • CLI로 변경 함수 목록 출력 (변경 안 된 함수는 정확히 제외)
  • 변경 전/후 테스트 기반 벤치마크 실행
  • before/after 비교 테이블 출력
  • 임계값 초과 시 경고 + exit code 1
  • 샘플 프로젝트 e2e 데모 동작

한계점

  • Python 전용 (다른 언어 미지원)
  • 테스트가 없는 함수는 측정 불가
  • 벤치마크 입력 자동 생성 미지원

프로덕트가 되려면

  • 다언어 지원: Tree-sitter로 AST 파싱 일반화
  • CI 통합: GitHub Action으로 PR마다 자동 실행
  • 벤치마크 자동 생성: LLM으로 테스트 입력 생성 → 테스트 없는 함수도 커버
  • 이력 추적: 커밋별 성능 추이 시각화
