Slide Last-Mile Editor

코드 기반 슬라이드의 미세 수정을 시각적으로 해결하는 양방향 동기화 에디터

  • 카테고리: Developer Tools / Presentation
  • 스택: Node.js, Express, Marp Core, vanilla JS
  • 날짜: 2026-03-09

Background

코드 기반 슬라이드 도구가 점점 늘어나고 있다.

Marp, Reveal.js, Slidev, 그리고 Claude Code 같은 AI 도구로 슬라이드를 생성하는 워크플로가 확산 중이다.

구조 생성은 빠르다. 문제는 미세 조정이다.

  • "slide 4의 오른쪽 하단 박스에서 폰트 크기를 줄여줘" — 이런 설명을 반복
  • CSS를 직접 열어서 margin, padding을 1px 단위로 수정
  • 프롬프트로 위치를 설명하는 것 자체가 비효율

→ 발표 준비 시간의 상당 부분이 이 last-mile 편집에 소모된다

Pain Point

커뮤니티에서 반복적으로 나오는 신호들:

3개 출처 모두 signal strength 3 — 일관된 고통

Solution

렌더링된 슬라이드 위에서 클릭·드래그로 미세 수정하면, 원본 마크다운이 자동으로 동기화된다

핵심 아이디어: 양방향 동기화

기존 도구들과의 차이점:

기존Slide Last-Mile Editor
Marp VS Code 확장: 미리보기만, 시각적 편집 없음렌더링 위에서 직접 편집
Slides.com: 처음부터 시각 편집, 코드 import 불가기존 .md 파일을 그대로 로드
Canva/Gamma: 자체 포맷, 마크다운 비호환원본 마크다운 소스 유지

코드 소스를 유지하면서 시각적으로 편집하는 도구는 현존하지 않는다

Demo

3패널 에디터 구성

  • Preview (좌측): Marp 렌더링 슬라이드. 텍스트 클릭 → contenteditable 인라인 편집. 드래그 핸들(⁞)로 위치 조정
  • Source (우측): 원본 마크다운 직접 편집. 입력 시 800ms 후 자동 저장 + 프리뷰 동기화
  • Diff: 원본 대비 변경사항을 추가(초록)/삭제(빨강)로 시각화

핵심 동작

# 특정 블록만 편집 — sourceLine으로 대상 지정
$ curl -X POST localhost:4567/api/edit \
  -d '{"sourceLine": 5, "sourceEnd": 6, "newText": "# 새 제목"}'

Key Decisions & Lessons

기술 판단

판단이유
Node.js + Express 선택Marp가 JS 생태계. @marp-team/marp-core를 직접 호출해서 렌더링 + 소스맵 주입을 서버 사이드에서 처리
markdown-it 플러그인으로 source-line 매핑렌더링 시 data-source-line 속성 주입. 블록 레벨 양방향 추적의 핵심
드래그 → CSS 주석 방식<div class="speaker-note" data-note-idx="6"></div> 형태로 .md에 삽입. 마크다운 파서를 깨뜨리지 않으면서 위치 정보 보존

반대 의견: "풀 스코프는 주말 초과 확실하며, 블록 레벨로 축소 시 핵심 가설 검증에 불충분할 수 있음" → 결과적으로 블록 레벨 축소가 맞았다. 인라인 레벨까지 가면 복잡도가 급격히 올라간다.

Results & Future

성과: 5/5 완료 기준 통과

  • Marp 마크다운 로드 → 슬라이드 렌더링
  • 인라인 편집 → 원본 .md 블록 자동 업데이트
  • 드래그 위치 변경 → .md에 인라인 스타일 반영
  • 편집 전후 diff 시각적 확인
  • 3장 샘플 슬라이드로 전체 기능 동작 데모
