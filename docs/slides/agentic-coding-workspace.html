Background

채팅 인터페이스의 구조적 한계

AI 코딩 에이전트(Claude Code, Cursor, Cline 등)는 모두 채팅 또는 CLI 기반 선형 인터페이스를 쓴다.

이 구조에서는:

  • 작업 단계가 뒤섞인다: 프롬프트 작성, 코드 실행, 결과 리뷰, 의사결정이 하나의 스트림에 섞여서 재사용과 분기가 어렵다
  • 데드타임이 집중력을 깬다: 프롬프트 → 10-30초 대기 → 결과 확인의 반복. 다른 일을 하기엔 짧고, 기다리기엔 긴 시간
  • 플랜 검토 지점이 없다: 에이전트가 계획을 세우고 바로 구현에 들어간다. 사람이 사전에 "이건 하지 마"라고 말할 타이밍이 없다

Pain Points

커뮤니티에서 반복적으로 나오는 이야기

#출처SignalPain Point
1HN3/3프롬프트→대기→확인 반복 리듬이 flow state 진입을 방해하고 집중력을 분산시킨다
2HN3/3채팅/CLI가 AI 작업을 선형 스트림으로 평탄화하여 작성-실행-리뷰-의사결정 분리가 어렵다
3GitHub Trending3/3AI 에이전트 실행 계획을 사전 검토할 인터페이스가 없어 결과물 재작업이 반복된다

세 개 모두 Signal 3/3. 여러 소스에서 일관되게 나온다.

Solution

Jupyter에서 영감 받은 셀 기반 AI 코딩 워크스페이스

한 줄 요약: 프롬프트 → 플랜 프리뷰(수정/삭제/승인) → 스트리밍 결과 → 셀 재실행

기존 솔루션과 다른 점:

기존 도구접근 방식한계
Claude Code, Cursor, Cline채팅/CLI 선형단계 분리 불가
Copilot Workspace이슈→플랜→코드 파이프라인이슈 기반 선형 워크플로
Plannotator플랜 시각 리뷰플랜만 해결, 워크스페이스 아님

우리 접근: 셀 타입을 분리(Prompt / Plan / Result)하고, 각 셀을 독립 실행 단위로 만든다. 에이전트가 코드를 쓰기 전에 플랜을 먼저 보여주고, 사람이 항목을 수정하거나 빼고 승인한 뒤 실행한다.

Results & Future

완료 기준 결과: 5/5 통과

  • 프롬프트 셀 실행 → mock 응답 스트리밍 표시
  • 플랜 프리뷰: 체크리스트 + 삭제/수정/승인
  • 셀 단위 독립 재실행
  • 코딩 시나리오 데모 (React Todo 필터 기능)
  • LocalStorage 상태 저장/복원

한계점

  • Mock 기반이라 실제 AI 응답 품질과의 연동은 미검증
  • 셀 간 의존성 그래프(DAG) 미구현
  • 드래그앤드롭 셀 재배치 미구현

프로덕트가 되려면

  • 실제 LLM 연동: Claude API / OpenAI API와 붙여서 실제 코드 생성 품질 검증
  • 셀 간 의존성: 한 셀의 결과가 다른 셀의 입력이 되는 DAG 구조
  • 파일 시스템 통합: 실제 프로젝트 디렉토리의 코드를 읽고 쓰는 기능
  • 정량적 비교: 채팅 대비 작업 완료 시간, 재작업 횟수 등 측정
