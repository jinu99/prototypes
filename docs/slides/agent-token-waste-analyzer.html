Agent Token Waste Analyzer

AI 코딩 에이전트의 토큰 낭비 패턴을 진단하고 최적화 포인트를 제시하는 CLI 도구

  • Category: Developer Tools / AI Agent Observability
  • Stack: Python, Rich, uv
  • Date: 2026-03-12

Background

  • AI 코딩 에이전트(Claude Code, Cursor 등)가 개발 워크플로우의 중심이 되고 있다
  • 에이전트는 작업 전에 코드베이스를 탐색해야 한다 — 파일 읽기, 검색, 컨텍스트 수집
  • 문제는 이 탐색 과정이 체계적으로 비효율적이라는 것
  • 토큰 예산의 절반이 실제 작업이 아닌 컨텍스트 수집에 소모되는 경우가 흔하다
  • 기존 도구(Langfuse, Portkey)는 "얼마나 썼는가"를 보여주지만, "어디서 왜 낭비인가"는 알려주지 않는다

Pain Point

커뮤니티에서 반복적으로 보고되는 토큰 낭비 신호들:

#출처SignalPain Point
1HN3/3서브에이전트가 같은 파일을 반복적으로 다시 읽어 토큰 낭비
2HN3/3모든 규칙/스킬을 매 프롬프트마다 컨텍스트에 로드
3HN3/3grep으로 코드베이스를 탐색하며 토큰 낭비 + 부정확한 결과
4HN3/3컨텍스트 수집에 전체 토큰 예산의 절반 소모
5Reddit3/3코드베이스 탐색에 컨텍스트 윈도우의 절반 소모

10개 신호 모두 Signal Strength 3/3 — 실제 사용자들의 일관된 고통

Solution

"얼마나 썼는가" → "어디서 왜 낭비인가"

핵심 전환: 모니터링(사후 추적)에서 프로파일링(원인 진단)으로

세 가지 낭비 패턴을 자동 감지한다:

패턴설명
repeated_read같은 파일을 세션 내에서 여러 번 Read
unused_searchGrep/Glob 결과를 이후 행동에서 활용하지 않음
duplicate_context매 턴마다 대량의 캐시를 재로딩, 극소량의 출력만 생성

그리고 세션별 유효 토큰 비율(effective token ratio)을 산출한다.

  • Parser: Parses JSONL line by line, extracts tool call sequences from tool_use types, aggregates tokens from usage fields
  • Analyzer: Three independent pattern detectors each identify waste using heuristic-based rules
  • Dashboard: Builds an at-a-glance terminal dashboard with Rich Panel/Table

Key Decisions & Lessons

1. 휴리스틱 기반 감지 vs LLM 기반 감지

  • LLM에 로그를 넘기면 정확하겠지만, 그 자체가 토큰 낭비다
  • 규칙 기반 휴리스틱으로 충분히 유의미한 패턴을 잡을 수 있었다

2. 캐시 토큰의 낭비 판단 기준

  • cache_read > 95% + output < 1%이면 "컨텍스트만 재로딩하고 일은 안 한 턴"으로 판단
  • 보수적으로 절반만 낭비로 산정 — 완벽한 정답은 없다

3. 스택: Python + Rich, uv 관리

  • JSONL 파싱은 표준 라이브러리 json으로 충분, Rich가 터미널 대시보드에 최적
  • 외부 의존성 최소화가 프로토타입에서는 올바른 판단

심의 점수: 문제 진정성 4.7 · 프로토타입 적합성 4.0 · 신선도 3.0 · 학습 가치 3.7

  • 실시간 모드: 세션 진행 중 낭비 감지 + 중단 제안
